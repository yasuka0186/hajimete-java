## 1-2. 制作背景

制作者には、Java／Spring Bootを使用したWebアプリケーション開発経験と、新入社員向けJava研修のサブ講師経験がある。本作品では、初心者がつまずきやすい「学ぶ順番」「環境構築」「専門用語」を意識し、迷わず短時間で学習を始められる体験を設計する。

なお、本作品はポートフォリオ用の架空サービスであり、実際の有料サービス、会員登録、決済、Javaコード実行環境は提供しない。

## 2-5. 出題仕様

### 第1問：コードの一部を入力

| 項目 | 内容 |
| --- | --- |
| 学習目的 | 文字出力に使う命令を知る |
| 表示コード | `System.out.____("Hello, Java!");` |
| 入力欄 | 空欄部分へ直接入力 |
| 正解 | `println` |
| 想定出力 | `Hello, Java!` |
| 主なヒント | `print`ではなく改行付きの`println`を使う／大文字と小文字を確認する |

### 第2問：1行全体を入力

| 項目 | 内容 |
| --- | --- |
| 学習目的 | 文字出力の1行を完成させる |
| 問題 | `Hello, Java!`と表示する1行を入力する |
| 正解 | `System.out.println("Hello, Java!");` |
| 想定出力 | `Hello, Java!` |
| 主なヒント | 文字列をダブルクォーテーションで囲む／行末のセミコロンを確認する |

### 第3問：表示内容を変更

| 項目 | 内容 |
| --- | --- |
| 学習目的 | 文字列を変更すると出力も変わることを理解する |
| 問題 | `Javaをはじめよう`と表示する1行を入力する |
| 正解 | `System.out.println("Javaをはじめよう");` |
| 想定出力 | `Javaをはじめよう` |
| 主なヒント | 命令部分は第2問と同じ／ダブルクォーテーションの内側だけを変更する |

## 2-6. 回答判定仕様

### 判定方法

- JavaScriptで入力文字列を判定する
- 入力値の前後の空白と改行を除去してから比較する
- 文字列内部の表記は模範解答と一致した場合に正解とする
- Javaコードを実際には実行しない
- 外部APIへ入力内容を送信しない

### 誤答分類とヒント

以下を優先順に判定し、エディター直下へ具体的なヒントを表示する。

1. 未入力
2. `System.out`または`println`の不足・誤記
3. 大文字・小文字の誤り
4. ダブルクォーテーションの不足
5. セミコロンの不足
6. 指定された表示文字列との不一致
7. その他の不一致

誤り箇所を断定できない場合は、誤った指摘をせず、模範となる構造を段階的に確認できる共通ヒントを表示する。

### 不正解時

- 結果欄に「もう一度確認してみよう」と表示
- エディター直下にエラー内容と該当箇所のヒントを表示
- 入力内容は保持
- 再入力して再判定できる
- 結果欄へフォーカスを移動する
- `aria-live`等で正誤とヒントを読み上げる

### 正解時

- 結果欄に「正解！」と表示
- なぜ正解なのかをやさしい言葉で解説
- コンソール風の領域に想定実行結果を表示
- 自動では次の問題へ進めない
- 「次の問題へ」を押した場合のみ進む
- 結果欄へフォーカスを移動する
- 正解・解説の要点を読み上げる

## 2-7. 進捗・見直し仕様

### 進捗表示

- 「問題番号＋進捗バー」を表示
- 完了問題は視覚表示とテキストの両方で区別する
- 未着手の未来の問題は選択不可
- 完了済みの問題は進捗部分から開いて見直せる

### 完了問題の見直し

- 初期状態は閲覧専用
- 保存済み回答、正解解説、想定出力を表示
- 「再挑戦」を押すと編集可能になる
- 再挑戦しても、それまでの全体完了実績は失わない
- 再挑戦後に正解した場合は、保存回答を新しい内容で更新する

### 再訪時

- 未完了の問題がある場合は、その問題から自動で再開
- 全問完了済みの場合は完了画面を表示
- 入力途中の内容も復元する

## 2-8. `localStorage`仕様

### 保存キー

`hajimete-java:trial:v1`

### 保存データ

```json
{
  "currentQuestionId": "question-1",
  "completedQuestionIds": [],
  "answers": {
    "question-1": "",
    "question-2": "",
    "question-3": ""
  }
}
```

### 保存タイミング

- 入力内容の変更時
- 問題移動時
- 正解時
- 再挑戦時

入力ごとの保存は短いデバウンスを入れ、過剰な書き込みを避ける。

### データ不整合時

- JSON解析に失敗した場合は初期状態へ戻す
- 存在しない問題IDが保存されている場合は無視する
- 画面が操作不能にならないようにする
- ユーザーへ技術的なエラー文をそのまま表示しない

### リセット

- 「最初からやり直す」を押すと確認ダイアログを表示
- 確認後に対象キーを削除
- 第1問の初期状態へ戻す
- キャンセル時はデータと表示を変更しない
- リセット完了後はページタイトルまたは第1問見出しへフォーカスを移す

# 3. テスト・品質基準

## 3-1. 対応ブラウザ

- Google Chrome 最新版
- Safari 最新版
- Microsoft Edge 最新版
- Firefox 最新版

重大なレイアウト崩れ、操作不能、主要機能の差異がないことを確認する。

## 3-2. 単体テスト（Vitest）

### 必須対象

- 回答の前後空白・改行を除去する処理
- 正解／不正解判定
- 誤答内容に応じたヒント選択
- 不明な誤答に対する共通ヒント
- 進捗データの保存・読み込み
- 壊れた保存データからの初期化
- 未完了問題の算出
- 全問完了判定
- リセット処理

### 合格基準

- 必須テストがすべて成功する
- 判定・保存の主要モジュールで、ステートメントカバレッジ80％以上を目安とする
- テストを通すためだけの本番仕様変更を行わない

## 3-3. E2Eテスト（Playwright）

### 必須シナリオ

1. LPの主CTAから`/trial/`へ移動できる
2. 月額プランが準備中表示で、申込処理へ進まない
3. 第1問で誤答すると具体的なヒントが表示される
4. 第1問で正解すると解説と想定出力が表示される
5. 正解後に自動遷移せず、「次の問題へ」で進む
6. 第1問から第3問まで完了できる
7. 全問完了後に結果、学んだ内容、次章の準備中案内が表示される
8. 入力途中で再読み込みしても、未完了問題と入力内容が復元される
9. 完了問題を進捗部分から開いて見直せる
10. 「再挑戦」を押すまで完了問題を編集できない
11. `Ctrl＋Enter`または`Command＋Enter`で判定できる
12. リセット確認をキャンセルすると状態が維持される
13. リセットを確定すると第1問へ戻る

### 合格基準

- Chromiumを使った自動E2Eがすべて成功する
- Safari、Edge、Firefox最新版は手動確認を併用する
- 主要導線に再現性のある失敗が残っていない

## 3-4. アクセシビリティ

### 必須基準

- セマンティックなHTMLを使用する
- 見出し階層を飛ばさない
- ページの主言語を日本語に設定する
- 画像に適切な代替テキストを設定する
- 装飾画像は読み上げ対象外にする
- フォーム要素とラベルを関連付ける
- キーボードのみで全操作を完了できる
- フォーカスを青色の枠で明確に表示する
- 正誤を色だけで伝えない
- 判定後に結果欄へフォーカスを移す
- 正誤・ヒント・解説の要点を読み上げられるようにする
- `prefers-reduced-motion`有効時は不要な動きを停止する
- テキストと背景のコントラストはWCAG 2.2 AAを満たす
- 200％拡大時にも主要機能を操作できる

### 合格基準

- axe等の自動検査で重大・深刻な違反が0件
- キーボード操作による手動確認が完了している
- VoiceOver等で判定結果が認識できる

## 3-5. SEO

### LP

- ページ固有の`title`と`meta description`
- OGPタイトル、説明、画像
- canonical URL
- 適切な見出し構造
- サービス名、Java、初心者、無料体験が不自然にならない範囲で伝わる本文
- `robots.txt`
- `sitemap.xml`
- ファビコン

### 無料体験ページ

- LPと重複しない`title`と`meta description`
- canonical URL
- 体験内容がHTML本文から理解できる
- Javaコードを実行する実サービスと誤認させない

### 合格基準

- 各ページのタイトルと説明が重複していない
- OGP画像とURLが公開環境で取得できる
- 壊れた内部リンクがない
- Lighthouse SEOが90点以上

## 3-6. パフォーマンス

### 実装方針

- 画像はWebPまたはAVIFを優先する
- 表示サイズに合った画像を使用する
- ファーストビュー以外の画像は遅延読み込みを検討する
- JavaScriptを機能単位に分割し、不要なライブラリを追加しない
- フォント読み込みによる表示遅延を抑える
- レイアウトシフトを防ぐため、画像サイズを指定する
- アニメーションは`transform`と`opacity`を中心にする

### Lighthouse目標

本番ビルド・公開URL・モバイル計測で、以下の各カテゴリ90点以上を目標とする。

- Performance
- Accessibility
- Best Practices
- SEO

点数だけで完了判定せず、主要操作と表示内容の正しさを優先する。

## 3-7. コード品質

- JavaScriptはES Modulesで機能別に分割する
- DOM操作、回答判定、ヒント判定、保存処理を分離する
- HTMLへ大きなJavaScriptを直書きしない
- SCSSは役割別に分割する
- クラス名はBEMを基本とする
- マジックナンバーや同一文言の重複を避ける
- 問題データは表示ロジックから分離する
- ESLint、Stylelint、HTML Validatorで重大エラーが0件
- コンソールエラーが0件
- 不要な`console.log`を残さない
- 公開リポジトリへ秘密情報を含めない

## 3-8. 表示・文章品質

- 初心者が理解できない専門用語には短い補足を付ける
- 「未経験者でも必ずエンジニアになれる」など、結果を保証する表現を使わない
- 実際には提供していない会員登録、決済、Java実行を利用できるように見せない
- 月額プランは「準備中」と明記する
- 架空サービスであることをフッターへ明記する
- 誤字脱字、仮テキスト、リンク切れを残さない

# 8. ポートフォリオ掲載用説明文

## 8-1. 短文版

プログラミング完全初心者向けの架空Java学習サービス「はじめてJava」を制作しました。サービス紹介LPに加え、コード入力、正誤判定、誤答別ヒント、解説、進捗保存を備えた全3問の無料体験を実装しています。Java研修のサブ講師経験を生かし、学ぶ順番に迷わない情報設計と、やさしい言葉で理解できる学習体験を意識しました。

## 8-2. 詳細版

### 制作概要

「はじめてJava」は、これからJavaを学び、ITエンジニアを目指すプログラミング完全初心者を想定した架空の学習サービスです。「何から学べばよいか分からない」「環境構築でつまずく」という課題に対し、6段階のロードマップとブラウザ上の無料体験を設計しました。

### 工夫した点

- LPから無料体験まで一貫したユーザー導線を設計
- 全3問を「一部入力→1行入力→表示内容変更」の順に構成
- 誤答内容に応じたヒントと、初心者向けの解説を表示
- `localStorage`で入力内容と進捗を保存し、再訪時に自動再開
- キーボードショートカット、フォーカス移動、読み上げ、動きの軽減へ対応
- VitestとPlaywrightで回答判定・保存・主要導線を自動テスト
- GitHub Pagesでの公開を前提に、ベースパスと静的配信を考慮

### 制作経験とのつながり

業務ではJava／Spring Bootを使ったWebアプリケーション開発を経験し、新入社員向けJava研修ではサブ講師として質問対応、エラーの一次切り分け、進捗・理解度の記録を担当しました。本作品では、その経験を初心者向けの文章、段階的な問題、誤答時のヒント設計へ反映しています。

### 使用技術

HTML／SCSS／JavaScript（ES Modules）／Vite／Vitest／Playwright／GitHub Pages

### 注記

本作品はポートフォリオ用に制作した架空サービスです。実際の会員登録、決済、Javaコード実行、有料プランは提供していません。
